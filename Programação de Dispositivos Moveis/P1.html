1 · Flutter, Dart e a estrutura do projeto

Por que estudarÉ a parte conceitual das aulas 2 e 3. Cai como questão curta ("o que o Flutter resolve?", "qual arquivo você altera para adicionar uma dependência?") e é pontuação fácil.

O que o Flutter resolve (aula 2)

Nas suas anotações: "Resolve um problema comum das aplicações modernas. É comum as aplicações terem mais de um ambiente." Ou seja, o mesmo app precisa rodar em Android, iOS, web, desktop. O Flutter permite escrever um único código e gerar o app para todos esses ambientes.

TermoO que é
FlutterFramework + engine de interface. Desenha a tela e oferece os widgets (botões, textos, listas).
DartA linguagem usada. "Ela que faz toda a parte do desenvolvimento" (anotação da aula 2).
WidgetTodo elemento da tela é um widget: texto, botão, espaço, coluna, a própria tela.
Documentaçãodocs.flutter.dev/learn/pathway

Instalação (aula 2)

  1. Instalar o Flutter (caminho usado em aula: C:\dev_flutter).
  2. Colocar o bin do Flutter no Path das variáveis de ambiente (para o terminal reconhecer o comando flutter).
  3. Instalar o Android Studio (SDK do Android e emulador).

Perguntas que você faria

Flutter é uma linguagem?
Não. Flutter é o framework; a linguagem é Dart.
Por que instalar o Android Studio se eu programo no VS Code?
Ele traz o SDK do Android e o emulador, que o Flutter usa para compilar e rodar o app Android.
Para que serve o Path?
Para o Windows achar o executável flutter em qualquer pasta do terminal. Sem isso, "flutter não é reconhecido como comando".
Por que não mexer nas pastas android/ios?
São geradas e configuradas pelo Flutter; alterar sem saber quebra o build. O professor recomendou mexer só em pubspec.yaml, lib e assets.

Scaffold: a estrutura de uma tela

Scaffold fornece o layout padrão de uma tela Material: appBar (barra superior com AppBar(title: Text(...))) e body (o conteúdo).

Como fica no código — esqueleto completo 
import 'package:flutter/material.dart';   // widgets Material

void main() {
  runApp(const MeuApp());                 // widget raiz
}

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});
  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,   // sem faixa DEBUG
      home: TelaContador(),                // primeira tela
    );
  }
}

class TelaContador extends StatefulWidget {
  const TelaContador({super.key});
  @override
  State<TelaContador> createState() => _TelaContadorState();  // liga widget ↔ estado
}

class _TelaContadorState extends State<TelaContador> {
  int numero = 0;                         // estado
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Contador')),
      body: Center(child: Text('$numero')),
    );
  }
}
Exemplo resolvido — classifique (a) Tela "Minhas Disciplinas" com 5 textos fixos → Stateless (nada muda).
(b) Tela de IMC que mostra o resultado depois do clique → Stateful (resultado muda).
(c) Lista de 4 produtos escritos no código → Stateless (Material 2, Ex. 4).
(d) Cadastro onde o usuário adiciona produtos → Stateful (a lista muda; Material 2, Ex. 5).

Perguntas que você faria

Por que o nome da classe de estado começa com _?
Em Dart, _ torna a classe privada ao arquivo. O estado só interessa ao próprio widget.
O que é @override?
Indica que você está sobrescrevendo um método herdado (build, createState, dispose).
Para que serve const?
Diz que o widget nunca muda; o Flutter pode reaproveitá-lo. Não pode ser usado em algo que depende de variável (Text('$numero') não pode ser const).
O que é {super.key}?
Parâmetro opcional key repassado à classe pai. Identifica widgets na árvore; nos exercícios só aparece por padrão.
O que é BuildContext?
A "posição" do widget na árvore. Usado, por exemplo, pelo Navigator (Módulo 10).

  • "Complete o código" com createState(), extends State<...> ou runApp faltando.
  • "Qual a função do Scaffold / do MaterialApp / de debugShowCheckedModeBanner?"

3 · Estado e setState()

Por que estudarÉ o coração das duas apostilas: está nos 13 exercícios que têm interação. Sem setState() o valor muda na memória, mas a tela continua mostrando o valor antigo.

Definições

  • Estado: qualquer dado que pode mudar enquanto a tela existe e que aparece na interface (int numero, String resultado, List<Produto> produtos).
  • setState(() { ... }): executa a alteração e avisa o Flutter que o build() precisa rodar de novo.
  • Regra de negócio no método: "a condição if (numero > 0) é verificada antes de executar a redução. Assim, a regra 'o contador não pode ser negativo' fica protegida no próprio método diminuir()" (apostila, Ex. 1).
toque no botão → onPressed chama o método → setState altera a variável → build() roda de novo → Text mostra o novo valor
Exemplo resolvido — rastreie o contador (Ex. 1) Início numero = 0. Toques: −, +, +, −, −, −.
− → 0 (bloqueado pelo if) · + → 1 · + → 2 · − → 1 · − → 0 · − → 0 (bloqueado).
Valor final exibido: 0. setState rodou 4 vezes (nos 2 cliques bloqueados ele nem é chamado, porque está dentro do if).
Como fica no código — Ex. 1 e Ex. 8 
int numero = 0;

void aumentar() {
  setState(() {
    numero++;              // muda e pede redesenho
  });
}

void diminuir() {
  if (numero > 0) {       // regra: nunca negativo
    setState(() {
      numero--;
    });
  }
}

// no build: onPressed recebe a REFERÊNCIA ao método (sem parênteses)
ElevatedButton(onPressed: diminuir, child: const Text('-')),

Seu Ex. 8 (estoque) com o desafio "Zerar com confirmação"

No seu exercicio8_controle_estoque.dart a confirmação é feita com uma segunda variável de estado, bool confirmandoZerar: o 1º clique só liga a flag e troca o texto do botão para "Confirmar"; o 2º clique zera. Qualquer Entrada/Saída cancela a confirmação. É um bom exemplo de estado que controla a própria interface (Text(confirmandoZerar ? 'Confirmar' : 'Zerar estoque')).

Perguntas que você faria

E se eu fizer numero++ sem setState?
A variável muda, mas a tela não é redesenhada; o número exibido fica parado até algum outro setState acontecer.
Posso pôr o if dentro do setState?
Pode (é o que o Ex. 3 e o seu Ex. 8 fazem). A diferença é que o setState roda mesmo sem mudança, o que é inofensivo. A apostila do Ex. 1 põe o if por fora.
Por que onPressed: diminuir e não diminuir()?
Com parênteses você chamaria o método na hora de desenhar e passaria o resultado (void). Sem parênteses passa a função para ser chamada no clique. Com parâmetro, use () => removerProduto(index).
Onde declarar a variável de estado?
Na classe _XState, fora do build. Se declarar dentro do build, ela volta ao valor inicial a cada redesenho.
StatelessWidget pode chamar setState?
Não. setState é um método de State; só existe em StatefulWidget.
Provável na prova
  1. Escrever um contador (ou estoque) com botões + e − que nunca fica negativo (Ex. 1 / Ex. 8).
  2. "O que acontece se removermos o setState() do método aumentar?"
  3. Rastrear o valor final após uma sequência de cliques (como o exemplo acima).

Por que SizedBox(height:) na Column e (width:) na Row?
O espaço é sempre no eixo principal: vertical na Column, horizontal na Row.
Qual a diferença entre child e children?
child recebe um widget (Center, Padding, Card); children recebe uma lista [...] (Column, Row, ListView).

5 · Entrada de dados: TextField e TextEditingController

Por que estudarExercícios 2 a 7 e o cadastro de produtos pedem campos de texto. O par TextField + controller + dispose() é cobrado junto: esquecer qualquer um dos três é erro clássico.

Conceitos centrais (apostila, Ex. 2)

"Cada TextField possui um controller. O conteúdo digitado é obtido com controller.text. Como os controllers permanecem ativos enquanto a tela existe, eles devem ser liberados em dispose(), antes da chamada a super.dispose()."

ElementoFunção
TextEditingController()Objeto que guarda o texto do campo
controller: nomeControllerLiga o campo ao controller
nomeController.textLê o texto digitado (sempre String)
nomeController.clear()Apaga o campo (Material 2, Ex. 5)
.text.trim()Remove espaços nas pontas (evita nome " ")
keyboardType: TextInputType.numberAbre o teclado numérico (não impede letras!)
InputDecoration(labelText:, border: OutlineInputBorder())Rótulo e borda do campo
dispose()Libera os controllers quando a tela é destruída
Como fica no código — Ex. 2 (cadastro) 
final TextEditingController nomeController = TextEditingController();
final TextEditingController idadeController = TextEditingController();
String mensagem = '';

void mostrarDados() {
  String nome = nomeController.text;     // lê o campo
  String idade = idadeController.text;
  setState(() {
    mensagem = 'Olá, $nome! Você tem $idade anos.';
  });
}

@override
void dispose() {
  nomeController.dispose();              // 1º libera os controllers
  idadeController.dispose();
  super.dispose();                       // por último, o da classe pai
}

// no build
TextField(
  controller: idadeController,
  keyboardType: TextInputType.number,
  decoration: const InputDecoration(
    labelText: 'Idade',
    border: OutlineInputBorder(),
  ),
),
Exemplo resolvido — quantos controllers? Ex. 2 (nome, idade) → 2 · Ex. 4 (dois números) → 2 · Ex. 5 (Celsius) → 1 · Ex. 6 (três notas) → 3 · Ex. 7 (peso, altura) → 2 · Cadastro de produtos (nome, preço) → 2. Regra: 1 controller por TextField, e cada um aparece no dispose().

Perguntas que você faria

Por que o controller é final se o texto muda?
O objeto controller é sempre o mesmo; o que muda é o conteúdo dentro dele. final impede trocar o objeto, não o texto.
O que acontece se eu esquecer o dispose()?
O app funciona, mas os controllers ficam ocupando memória depois que a tela fecha (vazamento de memória).
Por que super.dispose() vem por último?
Primeiro você limpa o que é seu; depois deixa a classe pai terminar a destruição. A apostila exige essa ordem.
TextInputType.number garante que só venham números?
Não. Só muda o teclado. Por isso a conversão usa tryParse com valor padrão (Módulo 6).
Por que controller.text de idade é String?
Todo TextField devolve texto. Para comparar ou calcular, é preciso converter (Módulo 6).
Provável na prova
  • "Para que serve o TextEditingController e por que chamamos dispose()?"
  • Escrever o Ex. 2 ou completar o método dispose() de uma tela com 3 campos.
  • Achar o erro: super.dispose() antes dos controllers, ou controller sem dispose.

6 · Conversão, decisão e fórmulas

Por que estudarExercícios 3 a 7 são o mesmo padrão com fórmulas diferentes. A apostila resume: entrada → conversão → decisão → atualização da interface. Se você domina tryParse ?? 0 e if/else, resolve qualquer variante (desconto, juros, área…).

Conversão de texto para número

"A expressão int.tryParse(idadeController.text) ?? 0 tenta converter o texto para int e utiliza 0 caso a conversão não seja possível." (apostila, Ex. 3)

ExpressãoResultadoPor quê
int.tryParse('18')18texto inteiro válido
int.tryParse('abc') ?? 00tryParse devolve null; ?? troca por 0
int.tryParse('12.5')nullint não aceita decimal
int.tryParse('')nullcampo vazio
double.tryParse('1.80')1.8ponto é o separador decimal

Valores conferidos rodando Dart. tryParse nunca lança erro; int.parse('abc') (sem "try") lançaria FormatException e travaria o app.

Decisão e validação

ExercícioDecisão
3 · Maioridadeidade >= 18 → maior; senão menor
4 · Calculadoran2 != 0 → divide; senão "Não é possível dividir por zero."
6 · Médiamedia >= 6 → Aprovado; senão Reprovado
7 · IMC (seu código)altura > 0; depois < 18.5 abaixo · < 25 adequado · senão sobrepeso

"A interface não elimina a necessidade de tratar regras e situações inválidas no código" (apostila, Ex. 4). Em Dart, 7 / 0 com double dá Infinity (não dá erro): por isso a validação é explícita.

Formatação da saída

  • '$nome' interpola uma variável; '${n1 + n2}' interpola uma expressão (precisa de chaves).
  • valor.toStringAsFixed(2) → texto com 2 casas: 24.69.
  • 'R\$ ...': o $ literal precisa de barra, senão o Dart tenta interpolar.
  • \n quebra linha dentro do Text (usado no seu Ex. 6 e 7).
Exemplo resolvido — os valores da apostila Ex. 5: C = 30 → F = (30 × 9 / 5) + 32 = 54 + 32 = 86. Em Dart, '$f' mostra 86.0; seu código usa toStringAsFixed(1) → "86.0 °F". A apostila escreve "86 °F": para bater exatamente, use toStringAsFixed(0).
Ex. 6: (7 + 8 + 6) / 3 = 21 / 3 = 7.0 → ≥ 6 → Aprovado. Outro: (5 + 7 + 5) / 3 = 5.67 → "5.7" → Reprovado.
Ex. 7: 80 / (1.80 × 1.80) = 80 / 3.24 = 24.69 → ≥ 18.5 e < 25 → Peso adequado. Outro: 57 / 1.62² = 21.72.
Ex. 3: campo idade "dezoito" → tryParse = null → 0 → "é menor de idade" (comportamento que a prova pode perguntar).
Como fica no código — Ex. 4 (métodos auxiliares + validação) 
double lerNumero1() {
  return double.tryParse(numero1Controller.text) ?? 0;
}

void dividir() {
  double n1 = lerNumero1();
  double n2 = lerNumero2();
  setState(() {
    if (n2 != 0) {
      resultado = 'Resultado: ${n1 / n2}';
    } else {
      resultado = 'Não é possível dividir por zero.';
    }
  });
}

Perguntas que você faria

Quando usar int e quando double?
int para contagens e idades (Ex. 3, estoque); double para qualquer coisa com casas decimais (notas, peso, altura, temperatura, preço).
O que é ???
Operador "se nulo": usa o valor da direita quando o da esquerda é null.
Por que criar lerNumero1() no Ex. 4?
As 4 operações leem os mesmos campos; o método auxiliar evita repetir a conversão 8 vezes. A apostila chama isso de "organização do código em métodos auxiliares".
O cálculo vai dentro ou fora do setState?
Tanto faz para o resultado. As apostilas fazem cálculo fora e só a atribuição da variável exibida dentro; o importante é a variável da tela mudar dentro do setState.
Por que o Ex. 7 valida altura > 0?
Altura vazia ou inválida vira 0 e a divisão daria Infinity. Seu código mostra "Informe uma altura válida.".

Por que estudarÉ o exercício que "reúne os conteúdos anteriores com os conceitos de estado e entrada de dados". Usa quase tudo da P1 numa tela só: forte candidato a questão de código longa.

Por que Expanded?

"Uma ListView vertical dentro de uma Column precisa receber uma altura limitada. Expanded faz a lista ocupar o espaço restante da tela e evita o conflito de altura ilimitada." Sem ele, o Flutter acusa Vertical viewport was given unbounded height e a tela não aparece.

Como fica no código — M2 Ex. 5 (partes essenciais) 
final List<Produto> produtos = [];

void adicionarProduto() {
  final String nome = nomeController.text.trim();
  final double preco = double.tryParse(precoController.text) ?? 0;

  if (nome.isEmpty || preco <= 0) {     // validação: sai sem fazer nada
    return;
  }
  setState(() {
    produtos.add(Produto(nome: nome, preco: preco));
  });
  nomeController.clear();                  // limpa os campos
  precoController.clear();
}

void removerProduto(int index) {
  setState(() {
    produtos.removeAt(index);
  });
}

// no build, último filho da Column
Expanded(
  child: produtos.isEmpty
      ? const Center(child: Text('Nenhum produto cadastrado.'))
      : ListView.builder(
          itemCount: produtos.length,
          itemBuilder: (context, index) {
            final Produto produto = produtos[index];
            return Card(
              child: ListTile(
                leading: const Icon(Icons.inventory_2),
                title: Text(produto.nome),
                subtitle: Text('R\$ ${produto.preco.toStringAsFixed(2)}'),
                trailing: IconButton(
                  icon: const Icon(Icons.delete),
                  onPressed: () { removerProduto(index); },   // closure com o index
                ),
              ),
            );
          },
        ),
),
Exemplo resolvido — rastreie a lista Ações: adicionar ("Mouse", "80") → adicionar ("", "50") → adicionar ("Teclado", "abc") → adicionar ("Monitor", "950") → excluir o 1º Card.
1) [Mouse] · 2) nome vazio → return, nada muda · 3) "abc" → preco 0 → preco <= 0 → nada muda · 4) [Mouse, Monitor] · 5) removeAt(0) → [Monitor].
Resultado: 1 Card, "Monitor — R$ 950.00". length = 1, isEmpty = false.

Perguntas que você faria

A lista é final, como posso adicionar itens?
final impede trocar a lista por outra (produtos = [...]), mas permite mudar o conteúdo com add/removeAt.
Por que onPressed: () { removerProduto(index); } e não onPressed: removerProduto?
Porque o método precisa do index. A função anônima "guarda" o index daquele Card e chama o método só no clique.
Por que os clear() estão fora do setState?
O controller avisa o próprio TextField quando muda; não precisa de setState para isso.
Por que tratar a lista vazia?
"Uma interface precisa prever o que será mostrado quando ainda não há dados." Sem isso a tela fica em branco e o usuário não sabe se deu erro.
Qual a diferença entre remove(obj) e removeAt(i)?
A apostila usa removeAt, que remove pela posição (o builder já tem o index). remove procura o objeto igual.
